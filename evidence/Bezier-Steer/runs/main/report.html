Bezier-Steer: varied correct solutions

At 64 attempts, Bezier solves 85.29% of held-out tasks, compared with 85.48% for straight routes and 86.91% for fixed routing. Complete request time is 5.81 ms for Bezier and 4.91 ms for fixed routing. The Bezier inference checkpoint is 1.278 MiB; the generator without an expert planner is 0.736 MiB and solves 85.74% of tasks.

With greedy decoding and the initial hidden state held fixed, varying only the curve across 64 attempts solves 14.71% of tasks, versus 10.55% for a deterministic attempt. At least two distinct correct structures appear on 0.52% of tasks. This shows that curve changes can steer the output. It does not by itself show that this is an efficient source of useful variety: the curve-only condition pays for 64 attempts and is a post-training intervention.

Fifteen trained models: five architectures and seeds 7, 19 and 42. What is measured

Total request latency includes CPU random draws/preprocessing, input transfer, GPU planning and decoding, output transfer, exhaustive checking and structural deduplication. It excludes startup and model loading. Each seed's timing is the median of three repeats of mean per-request latency across 16 validation tasks. Candidate budget is chosen by measured latency alone for the wall-budget tables. This is an average-latency comparison, not a hard response-time guarantee. Raw repeats and allocator memory are retained. No GPU training ran concurrently with timing. Checkpoint size excludes the training-only posterior, optimizer, data and shared runtime.

Scope and limitations

These are finite Boolean microprograms, not natural-language coding, repository repair, visual design, or a general intelligence benchmark. Syntax validity is enforced by a shared grammar and is not a learned-coherence result. Verified outputs are exact in this finite domain, but the fraction of tasks solved and the many incorrect raw candidates must still be considered. Normalization removes dead gates, commuting/associative rearrangements and simple identities; other superficial rewrites may remain. Structural diversity does not imply algorithmic novelty. Three seeds give limited uncertainty estimates. All depths were trained, but there is no adaptive halting or branch-and-revise loop. The learned Gaussian prior may not capture every valid program mode. Latent variation also affects the initial hidden state, so curve interventions are needed to attribute changes to geometry. Post-training interventions can move the network away from its training distribution and are not independent trained baselines. The CUDA implementation is eager, with TF32 disabled; desktop scheduling causes timing variation. The data distribution favors functions with multiple observed implementations. Random search is a simple unpruned generator baseline, not an optimized symbolic solver.
