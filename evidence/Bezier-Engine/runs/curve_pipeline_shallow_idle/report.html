GPU variables / CPU Bézier equation: pipeline measurements with operator-confirmed idle background

The operator reported other compute workloads idle for this run. That context is recorded, not an independent process audit. Measurements describe the tested runtime on this machine; this small repeat count and schedule sweep do not establish a universal winner or independently isolate a CPU-thread saturation point.

Raw measurements and environment · Plain-text report · Frozen protocol

Intel(R) Core(TM) Ultra 7 265KF; NVIDIA GeForce RTX 5090; PyTorch 2.10.0+cu128. 108 schedule/workload configurations, 3 randomized rounds per configuration, 3 complete execution(s) per timed observation. All numbers below are median wall time for the complete workload, in milliseconds; lower is better.

The GPU producer uses the project's PortsAndCurve MLP and control-point mapping. The CPU evaluates the same cubic Bernstein weighted sum. Fixed sample-time coefficients are cached equally in every schedule. Schedules share identical reproducibly generated random inputs and random weights, as specified by the recorded settings and frozen source; this is an FP32 execution experiment with TF32 disabled, without training or model-quality claims.

Weights use seed 20261125; inputs use a separate CPU generator with seed 20261126. The separate input generator gives shallow and deeper networks identical inputs despite different parameter counts. Weight values differ across depths; schedules within each depth use identical weights and inputs.

Control-point hidden layers are the nonlinear layers inside the network that calculates the four control points. Their architecture is input width → router width repeated once per hidden layer → 12 output values, with SiLU after each hidden layer. This count is separate from recursive tree levels and does not count the sphere's expert layers. The child embedding is used only between nonterminal levels in the synthetic tree.

Inputs start on CPU and final outputs are usable on CPU. Timing includes required transfers, scheduling, waits, and pipeline fill/drain; it excludes construction, reusable-buffer setup, warmup, and validation. Native Torch threads are one in hybrid schedules. Streams and per-slot pinned buffers permit overlap; no device timeline was collected to quantify physical overlap.

This is an eager Python/PyTorch runtime without CUDA Graphs or fused kernels. Python dispatch, kernel launches, transfers, and synchronization affect the timings. These measurements do not establish that a CPU/GPU split cannot work in a different implementation or workload.

Verification and reproducibility

All 108 configurations passed output checks before and after timing in every round. The largest recorded warmup absolute error versus the CPU reference was 7.92e-06. Output tolerances were rtol=1e-4 and atol=2e-5. The cached-basis evaluator was separately checked against the original Bézier function with rtol=1e-6 and atol=1e-7. The report recomputed every median and verified all frozen source hashes.

For a clean comparison, run from Bezier-Engine with other compute workloads idle and use a new output directory. Use --load-context operator_confirmed_idle only after confirming that condition; the flag records the operator's observation and does not enforce idleness. Preserve this run. Source snapshots identify the exact implementation used for these measurements; current source may have later maintenance changes.
