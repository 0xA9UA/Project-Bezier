Memory Sphere 7B

Full-stack custom sphere computation · 7,346,916,807 parameters · no pretrained teacher or imported model weights

The larger architecture runs and learns on the local RTX 5090. This is an early from-scratch training pilot, not a general coding assistant. The 7B target replaces the earlier 14B proposal.

The trained pilot passed 0/60 stages at every evaluated visit budget, including adaptive stopping. It often emitted finish before making a useful edit. Lower token loss did not translate into completed programs.

Training completed 600 updates, supervising 14,612 sampled answer tokens and presenting 125,058 context tokens, in 8.6 minutes including validation and checkpoint saves. Peak training tensor allocation was 20.02 GiB; PyTorch reserved up to 21.70 GiB. These are not whole-device peaks.

What the model actually does

There are 64 independent 10,496 × 10,496 region matrices, a 4,096-dimensional state, 512-dimensional memory keys, and four cyclic scratch slots. Each visit evaluates four addressed regions. The 3D coordinates locate regions; high-dimensional activations still carry content. Input formation and internal recurrence use the same field, and the model has its own token embedding and surface-address readout.

The 64 matrices contain 7.051B parameters. At most 0.737B shared-plus-selected parameters are available per token visit, counting every shared parameter as an upper bound. Sparse dispatch saves computation; all weights still occupy 13.685 GiB in BF16. Text KV storage grows with real context length. Internal scratch slots remain fixed with depth. A learned surface exit is not proof of correctness.

What this does and does not establish

The checkpoint audit verifies all tensor shapes and hashes. All 64 regions received optimizer updates and have observed changes in sampled weights. Reduced-size checks cover equivalence to the original dense sphere calculation, causal caching, batched generation, and optimizer-in-backward equivalence. Independent regrading found 0 scoring discrepancies. All 32/32 representative full-size first-action checks matched serial generation; these are not a complete serial task evaluation.

The entire stored training corpus has only 2.566 million tokens and is mostly generated program-chain examples. The pilot sees much less than that. It cannot support a claim of broad language-model pretraining. There is one seed, no newly trained 7B straight-route or ordinary-recurrence control, and no matched-compute claim against pretrained models. The multi-exit loss gives shorter exits more direct supervision. Extra visits must earn their value in task results, not parameter count.
