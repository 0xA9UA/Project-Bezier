Memory Sphere experiment

Memory Sphere

Full-stack sphere computation, clustered KV memory, Bézier routing and learned surface exits.

Adaptive Bezier passed 6/120 stage-runs; direct routing 7/120; straight routing 6/120. These are two fits on the same 60 stages.

This trial did not establish a Bezier coding advantage or larger-model parity. It demonstrates a working implementation with bounded internal memory; stronger task competence remains unproven.

This is a 1,538,295-parameter model trained from scratch. It contains no Qwen processing layers or decoder. The small controlled test does not establish general coding-agent capability or settle the broader architectural hypothesis.

What was implemented

One shared spatial processing bank, sixteen learned region addresses, a 256-dimensional state, soft key clusters and four overwritten scratch slots. Input formation makes one pass through this same bank. The displayed step budget counts subsequent recurrent reasoning visits; timings include input formation. Each Bézier segment is sampled at thirds, then replanned from the current state. A trained per-token halt predictor chooses when to emit through a learned surface address.

Coordinates address processing regions; they do not replace the high-dimensional state or assign an independent address to every scalar weight. The final surface segment is an output-address transition, not a further sequence of reasoning operations or a guarantee of correctness.

Limits of the measurements

All sixteen operators are computed before mixture selection: this implementation does not demonstrate sparse-dispatch acceleration. Scratch KV capacity stays fixed with internal depth, while real text still grows context memory. The bounded-memory property comes from weight sharing and overwriting four scratch slots; it is common to all three routing controls. Reported memory is PyTorch allocated memory, excluding CUDA context/driver/display overhead; it is not total device usage. Whole-device snapshots during the small-model benchmark were about 1.03 GiB, including display/driver activity; these are not measured process peaks. Training autograd memory grows with depth. Batched quality runs may compute extra work for rows whose logical halt occurred earlier.

Tasks are 24 generated short pointer programs, twelve longer chains, four three-stage updates, and twelve unused MBPP test functions. The bounded tools support one Python file and restricted tests, not unrestricted repository or shell work. Syntax learning in the development runs was stronger than dependency following. Training size, architecture and optimization remain confounded in any negative capability result.

The multi-exit language loss encourages early prediction; this is one training recipe, not a comprehensive test of adaptive-depth training. Generated dependency depth is not a guarantee of required internal reasoning depth: a model can emit a runtime graph interpreter. MBPP IDs are unused by the prior local pilots; pretrained external models may have seen public MBPP content.

Final small-model quality runs use batches of up to 48 independent tasks; external reference quality runs use batches of two. Compare the separate batch-one probes for inference resource costs. The original smaller-batch Bezier seed-7 quality runs are retained as an engineering archive and replayed at the final batch size. Protocol amendments and generation/regrading audits record this change.
