Bézier Think: local coding-agent pilot

Complete: 34/34 conditions.

Qwen2.5-Coder 1.5B, BF16, rank-8 attention adapters and continuous latent recurrence. Three recurrence methods × five step counts × two seeds; two trained zero-step controls; unmodified 1.5B and 14B controls. Each condition uses 12 held-out MBPP functions plus four three-stage authored projects. Project code carries across stages. Hidden tests never enter feedback or model selection.

Observed result

Additional latent computation stayed within a small memory footprint, but this adaptation did not make the 1.5B model competitive with the 14B control. Recurrent variants passed 9–10 of 24 stages, compared with 20 for 14B and 9 for the trained zero-step control. The small models completed no full projects; 14B completed 2 of four.

There was no consistent quality increase from 2 to 32 steps. Every paired 95% interval for Bézier versus ordinary recurrence included zero. At 32 steps Bézier averaged 1.35 seconds for the common 32-token probe, versus 1.15 seconds for 14B. Their batch-one peak CUDA allocations were approximately 2.92 and 27.65 GiB, respectively.

The memory result supports running more internal computation without loading a larger model. It does not establish a special Bézier memory advantage: straight and ordinary recurrence had almost the same footprint. Weight storage and prompt processing dominated the observed peak, while latent steps still added KV-cache entries. These findings apply to this small local adapter pilot and do not rule out benefits from other architectures or stronger training.

Timing: quality evaluation uses batches of four. Wall time includes all tasks and failures. Single-request timing uses a fixed validation prompt, batch one, three shuffled repetitions, and a 32-token cap. Check actual output lengths in summary.json. CUDA allocation excludes the display driver and other processes; reserved peaks are in raw traces.

Limits: this is a small restricted-Python benchmark with terminal-style tools, not arbitrary shell execution or a general coding-agent leaderboard. MBPP pretraining contamination is unknown. Two seeds and 16 task families provide limited evidence. The small model’s lower weight memory comes primarily from its size; recurrence adds computation and cache entries, and does not compress the base weights.

Training teaches this tool protocol as well as code. Comparisons with the trained zero-step control are essential. The restricted evaluator excludes some otherwise ordinary Python features, including typing imports and print; these can cause failures even when the intended function is plausible. Per-condition failure categories in summary.json distinguish these failures from failed function checks. The benchmark scores are for the declared environment, not general Python correctness.
